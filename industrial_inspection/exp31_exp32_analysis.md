# exp3.1 与 exp3.2 模型比较

分析日期：2026-10-12。分析对象是两次训练目录中的 `weights/best.pt`。

结论：exp3.2 确实包含 exp3.1 的全部图片和原标注，但新增图片高度集中在一段连续视频，并存在明确的空槽/满槽矛盾标注。共同验证集上的整体 mAP 基本持平；按当前视频脚本使用的置信度 0.6 测试，3.2 对满槽漏检更多、误检略少。现有证据支持保留 3.1 作为业务基线，优先清理数据，再判断是否升级到 3.2；尚不能证明 3.2 在所有新视频上都更差。

## 1. 训练与数据核对

| 项目 | exp3.1 | exp3.2 |
| --- | ---: | ---: |
| 实际架构 | YOLOv8n | YOLOv8n |
| 初始权重 | yolov8n.pt | yolov8n.pt |
| 输入尺寸 | 1280 | 1280 |
| batch / 训练轮数 | 32 / 100 | 32 / 100 |
| 图片总数 | 443 | 970 |
| 训练 / 验证图片 | 354 / 89 | 776 / 194 |
| CSV 中 mAP50–95 最佳轮次 | 98 | 84 |

训练参数、类别顺序和数据增强配置一致，配置差异仅涉及数据路径和运行目录。3.2 是重新从 yolov8n.pt 训练，并非从 3.1 的 best.pt 接着训练。虽然项目目录叫 yolov10，但这两个被比较的模型实际都是 YOLOv8n。

通过图片 SHA256 比对确认：443 张旧图片全部保留，旧图片对应的 YOLO 标注数值也全部保持不变，没有丢失旧数据或更换类别编号。

- 3.2：`C:/Users/win10/xanylabeling_data/trainer/ultralytics/datasets/detect/detect_classes_20261008_150534`

### 新增数据改变了训练分布

新增 527 张均为 frame_200101 至 frame_200627，没有给其他两个序列增加图片。按文件编号分组的分布如下；序列含义还结合画面内容判断。

| 图片组 | 3.1 总数 / 训练数 | 3.2 总数 / 训练数 |
| --- | ---: | ---: |
| frame_0xxxx | 200 / 159 | 200 / 162 |
| frame_1xxxxx | 142 / 115 | 142 / 113 |
| frame_2xxxxx | 101 / 80 | 628 / 501 |

第三组在全部数据中的占比由 22.8% 升至 64.7%，在训练集中的占比由 22.6% 升至 64.6%。连续帧很相似，增加图片数量不等于增加同等数量的新场景；这会使训练更偏向该视频的视角、反光、遮挡和动作状态。是否因此造成性能回退，需要用清理后的数据做对照训练才能证明。

## 2. 指标为什么不能只看训练结果

模型 best.pt 保存的原始指标：

| 原训练指标 | exp3.1 | exp3.2 |
| --- | ---: | ---: |
| Precision | 96.69% | 97.34% |
| Recall | 95.41% | 94.83% |
| mAP50 | 97.67% | 98.21% |
| mAP50–95 | 75.89% | 84.04% |

3.2 的原验证指标看起来更好，但两版验证集不相同。旧图片的划分发生了变化：70 张从旧 val 进入新 train，73 张从旧 train 进入新 val，两版只有 19 张共同验证图片。新增连续帧也进入了 3.2 的验证集。

因此，这些指标不能直接证明新视频效果提升。直接拿任一版本的完整验证集比较，也会包含另一个模型见过的训练图片。随机按帧划分还可能让同一段视频的近邻帧同时出现在训练和验证中，使指标高估对新视频的泛化。

## 3. 同条件比较

使用同一个推理/验证框架、imgsz=1280、NMS IoU=0.7，重新评估两模型。共同验证集有 19 张、137 个标注对象。

| 共同验证集指标 | exp3.1 | exp3.2 |
| --- | ---: | ---: |
| 全类别 mAP50 | 99.27% | 98.78% |
| 全类别 mAP50–95 | 84.42% | 84.46% |
| 满槽 AP50–95 | 86.50% | 85.77% |

整体几乎持平，并非 3.2 明显优于 3.1。上述 AP 综合多个置信度阈值，不能直接代表脚本 conf=0.6 时的业务效果。

另按视频脚本的设置逐图预测，用类别一致、IoU≥0.5 的一对一匹配统计固定阈值效果：

| 满槽、conf=0.6 | exp3.1 | exp3.2 |
| --- | ---: | ---: |
| 正确检出 / 标注总数 | 75 / 76 | 72 / 76 |
| 漏检 / 误检 | 1 / 3 | 4 / 2 |
| Recall | 98.68% | 94.74% |
| Precision | 96.15% | 97.30% |

对“放了几片晶圆”这种依赖完整检出的任务，当前小样本结果更支持 3.1；对减少满槽误报，3.2 略有优势。conf=0.25 时，两模型均正确检出 75/76 个满槽，但 3.1、3.2 的满槽误检分别为 5、7 个。因此，3.2 并非在每个阈值下都更少误检；阈值应按模型分别校准。

这些 19 张图片都曾用于两模型选取最佳 checkpoint，且包含邻近视频帧。样本少、不是独立测试集，不能将上述百分比当作实际部署准确率。

训练权重来自 Ultralytics 8.4.163；重新评估使用本项目 Ultralytics 8.1.34，因此复测数值与原日志会有差异。两模型的复测框架相同。固定阈值统计使用逐图 predict，框匹配 IoU=0.5；它与框架按最佳 F1 工作点报告的 P/R 是不同统计口径。

## 4. 新视频抽样结果

对以下两段视频各抽 16 帧，两模型处理完全相同的画面，共得到 64 组模型输出：

- `I:/youyan/test_dataset/camera_B_20260918_144258.avi`
- `I:/youyan/test_dataset/camera_B_20260918_161258.avi`

设置：imgsz=1280、conf=0.25、NMS IoU=0.7，并从原输出筛选 conf≥0.6。为比较模型本身，没有加 ROI 或槽位二次去重。

| 32 个抽样帧中的槽位框数量 | exp3.1 | exp3.2 |
| --- | ---: | ---: |
| conf≥0.25，空槽 + 满槽 | 49 + 73 | 46 + 69 |
| conf≥0.6，空槽 + 满槽 | 44 + 70 | 44 + 69 |

抽样没有显示 3.2 全面明显退化，但个别位置的类别、置信度发生变化。比如 144258 视频第 6028 帧的同一位置（两框 IoU=0.912）：3.1 判为满槽、置信度 0.882；3.2 判为空槽、置信度 0.254。在 conf=0.6 下，3.2 的框消失。单纯降低阈值会恢复空槽框，并不能自动纠正其空满判断。

- [该帧 exp3.1 结果](E:/GitHub/yolov10/industrial_inspection/video_results/exp31_exp32_analysis/camera_B_20260918_144258_6028_exp3.1.jpg)
- [该帧 exp3.2 结果](E:/GitHub/yolov10/industrial_inspection/video_results/exp31_exp32_analysis/camera_B_20260918_144258_6028_exp3.2.jpg)

这两段视频尚未建立人工核实的测试真值，不能将更多框当作更准确，也不能计算可靠的新视频准确率。抽样中没有发现 IoU>0.85 的高度重合槽位预测对，这不代表整段视频没有重复框或多个较低 IoU 的框指向同一槽位。

## 5. 建议的改进顺序

1. 先复核上述 5 张冲突图片，再检查新增数据中的空满混淆、漏标、遮挡、反光和槽位框定义。修正原始 JSON 后重新导出数据，避免训练快照和源标注不一致。
2. 对连续帧抽稀，优先补充不同视频、日期、光照、遮挡以及真实放取状态的图片。平衡视频来源和状态，不必强行让类别数量完全相等。
3. 按完整视频或操作片段划分 train/val/test，固定测试集。不要让同一动作的近邻帧跨集合；新数据只扩充训练集，保持比较口径。
4. 保留 exp3.1 作为基线。使用相同配置分别训练“清理并平衡的数据”和原 3.2 数据，通过独立测试比较，才能确定数据变化是否造成退化。之后再考虑更大模型或调整训练参数。
5. 对下方四个槽，统一 ROI，分别选择置信度阈值，记录逐槽空满准确率、漏检率、空满翻转次数、整帧数量是否正确，以及放取事件是否漏报。ROI 能限定位置，无法修复标签冲突；去重能减少重复框，无法保证空满类别正确。

本次完成了数据审计、6 组验证集复测、共同验证集固定阈值统计、两段视频抽样对比。没有修改原始标注、重新训练模型或切换视频脚本默认权重。
