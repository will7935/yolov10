# ROI自动分组与四槽检测

直接运行 [predict_slot_groups.py](E:/GitHub/yolov10/industrial_inspection/tools/predict_slot_groups.py)。
复用原 predict_video.py 的视频路径、权重、ROI 和 UI7V 界面，不修改原入口。

## 本版实现范围

- 默认确认舱门把手打开后才启动原来的下料→上料流程；确认关门后结束本轮检测，冻结二十槽统计。
- 每组正式槽号分别确认四个满槽后输出“游星片N：已放满（4/4）”；关门时输出“已放满（20/20）”或“未放满（N/20）”。
- 用ROI内YOLO检测框的中心初始化槽位。下料时若仅检测到三个几何关系有效的槽，且几何关系表明缺失位置是S4，可按约90°环形布局推算S4中心；若缺失的是其他槽则继续等待真实框。当前相机按左上S1、顺时针1→3→4→2的二维环序编号，
  并用S2通常位于S3下方辅助核验；不把四槽全局按y排序。正式编号后不再重排。
- 起始组号可配置为 1..5；当前单点换组模式下，旧组任一真实中心越出ROI就立即递增组号，开始跟踪新点。
  新点仅显示ByteTrack轨迹ID并记录空满；收齐三条或四条可靠轨迹且几何稳定后，一次性映射到正式槽号S1..S4，状态历史随轨迹继承。ByteTrack ID不是槽号，不能单独作为S1..S4使用。
  第四槽延迟出现时，可使用此前至少三槽已确认的停稳几何作为身份参考，不要求四槽同时无遮挡。
- 单点换组后的新组按真实中心逐点匹配（当前40像素），不把一两个点的移动外推到其他槽。
  四条轨迹均已建立后，至少三个可靠点支持有界相似变换时，才允许跟随暂时遮挡槽的参考位置。
  旧组退出时若S4来自三点几何推算，会用仍可见的三条真实槽估算同一载体运动，并保留为旧组预测轨迹，
  直到该槽重新被真实框接管或旧组离开ROI缓冲带，避免转动中的G3-S4被当作G4槽位。
  首组及多点模式在小幅连续移动/旋转时，至少三个可靠匹配槽共同支持相似变换，才更新未检出槽的预计位置。
  当前检测中心与编号参考位置分开保存；只有一两个槽可见时仅显示各自的检测中心，
  不改变整组关联模板，避免把框中心抖动外推为整组运动或造成槽间距不断缩小。
- 输出组号、槽号和 empty / filled / unknown，支持手部遮挡和空满冲突抑制。
- 空满状态需要连续满足时间和帧数条件；初次确认状态不算操作事件。
- 首组候选四槽出现时开始记录；单点换组后的新组从第一个新点开始记录，不要求四槽同时出现，也不等待停稳。
  组身份确认后补报有效临时轨迹上已有可靠证据的取放事件，保留原始操作时间区间。
- 上料记录 empty→filled，下料记录 filled→empty；两种工序使用同一顺时针环。
- 保存每帧四槽结果、取放事件和摘要，UI 和输出视频显示相同编号与状态。
- 沿用现有权重和ROI，每帧整图推理一次；操作中已编号槽被整图漏检时，自动裁剪局部图补检。
  局部补检只补充空满观测，不改变槽位轨迹、不触发换组，也不用于新组初始化。
- 组号来自已知起始组号与换组次数，不是凭单张图片识别物理游星片。
- 默认自动运行 `下料 G1→G5 → 上料 G1→G5`。下料G5实际退出ROI后立即进入上料G1，
  上料G5退出后显示“工序结束”。未确认完成的下料槽仍记录为未完成，不会阻塞下一物理组的跟踪。
- 空满状态优先使用YOLO连续确认。仅S4的手接触用于补足状态变化；接触达到门限并离开后，若YOLO仍持续为unknown，
  且接触前有已确认状态，则按原状态反转：`empty→filled`、`filled→empty`；推断事件标记
  `confirmation_source=hand_contact`。下料时若接触前一直没有确认状态，则在有效手接触达到门限后，先以`filled`
  作为初始基线，离手后仍为unknown时推断为`empty`。如果YOLO直接确认新状态，
  保留YOLO结果；若确认的仍是接触前状态，则取消接触推断。接触后先等待短暂恢复检测，仍为unknown才补状态。
  满槽核验单独统计可靠确认的filled占用状态，首次看见已经放满也可以计入；不会凭接触、遮挡或转位次数补足数量。

## 舱门控制与二十槽核验

直接使用原入口，`HATCH_CONTROL_ENABLED=True`默认开启新功能，保留现有先下料五组、再上料五组的顺序。
开门前仍推理把手，但不更新槽位轨迹、空满状态和操作事件。开门后按原有ROI规则检测，
上料五组结束后继续等候关门；确认关门时停止处理视频，并输出最终满槽结果。
如果关门时当前组尚未转出ROI，也纳入统计，不要求最后一组必须退出。

把手模型只有`hatch_handle`类别，开关由固定相机中的中心位置判断：

```python
HATCH_OPEN_POLYGON = ((.39,.01),(.495,.01),(.495,.18),(.39,.18))
HATCH_CLOSED_POLYGON = ((.495,.18),(.72,.18),(.72,.49),(.495,.49))
HATCH_CONFIRM_SECONDS = .3
HATCH_MIN_CONFIRM_FRAMES = 3
HATCH_MAX_GAP_SECONDS = .25
```

多边形坐标按画面宽、高归一化，当前区域按camera_B视频中的开、关把手位置确定；换机位须重新标定。
同一状态须同时满足确认时长和最少帧数，相邻支持证据间隔不得超过0.25秒。
把手漏检、低置信度、区域外检测或同时出现开关位置都不能直接触发关门。
视频开始时已关闭不算本轮结束，须先确认开门；关门只结束本轮，不把下料槽状态当作上料结果。

统计按正式的G1～G5、S1～S4身份去重，使用每槽最近确认的filled状态；空槽、未知槽、临时身份和未出现的组均不算满。
已经退出的上料组保留本轮最后确认状态，退出后的短时补检结果仍能更新该组。
每组确认满槽时及时输出；退出核验结束仍不满时输出未放满；关门对五组和20槽统一出最终结果。
满槽核验与操作顺序判定独立，可能已放满但顺序仍为pending。
视频结束或手动停止而未确认关门时，只保存阶段统计，`finalized=false`，不发布关门最终结论。

新增`inspection_events.jsonl`保存开关门、逐组满槽和最终核验事件，
`loading_fullness_report.json`及同名`.txt`保存五组数量、已满槽号、空槽号、未知槽号及20槽结果。
同一结果写入`summary.json`的`inspection`、`inspection_events`及`loading_fullness_report`，UI状态栏与日志同步显示。
若需重放已有槽位算法用例而不使用门控，设置`HATCH_CONTROL_ENABLED=False`。

## 换组判断

```text
首组至少三槽初始化（下料可推算缺失中心） → 操作中 → 任一真实中心越界 → 新组逐点记录 → 几何与停稳核验 → 正式编号
                            ↓
                 遮挡/匹配证据不足：组身份待确认，保持组号
```

1. 每槽必须实际检测到从ROI边界内4像素以上，移动到边界外4像素以上；未检测到的预测点不计越界。
2. 当前配置为单点换组：任意一个已编号槽的真实检测中心从ROI内越到ROI外，
   同一帧关闭旧组并切到下一组，不再等待多个槽、停稳或退出计时。
3. 新组第一个点出现时即跟踪、显示并记录状态；还没出现的槽保持unknown和空坐标。
   单点越界只触发换组，不把预测点或漏检点当成越界证据。
4. ROI外40像素内只保留能与当前组编号匹配的框；这些框只用于退出跟踪，不确认空满，也不建立新编号。
5. 旧组关闭后继续逐点跟随旧中心，排除残留点；切组帧中出口侧未匹配的整图槽框也保留为旧尾部，
   只作隔离，不凭空赋予旧槽号。新点按NEXT_GROUP_MATCH_DISTANCE_PX（当前40像素）一对一匹配并拒绝歧义。
   EXIT_DIRECTION已知时，首批新轨迹须从入口侧建立，旧尾槽漏配或失联超时都不能直接获得新组身份。
   至少两条入口轨迹建立后，允许接收进入时曾被遮挡的其他槽；已有新轨迹可以走完整个ROI。
6. 四条轨迹都曾可靠看见，且至少三个可靠点支持几何停稳达到NEXT_GROUP_STABLE_SECONDS后，映射一次正式槽号。
   第四槽只在后续转位时露出时，可用此前三槽的停稳参考核验身份；至少两个可靠对应点才允许有界坐标还原，
   两点只能支持相似变换，不能外推隐藏槽的实时轨迹。实际编号用二维环序与S2/S3上下关系消除歧义。
   临时阶段确认的取放事件在映射时补报，原始时间区间不变。
   正式编号后继续沿用逐点匹配，空满框中心偏移只更新对应槽；不可见槽保留上次位置。
   空满判断仍满足CONFIRM_SECONDS及MIN_CONFIRM_FRAMES；手遮挡或空满冲突仍输出unknown。

EXIT_MIN_SLOTS大于1时保留原多点退出模式，使用EXIT_CONFIRM_SECONDS；NEXT_GROUP_STABLE_SECONDS对新组正式编号同样生效。

临时轨迹超过INITIALIZATION_HISTORY_SECONDS仍无可靠匹配时清理，状态和事件不转接给替代点。
仍可追踪的临时身份上已确认的取放事件一直保留到正式编号，不按事件年龄清除；
第四槽长期遮挡不会丢掉前三槽的操作时间。该窗口仍限制过期原状态基线，不能据此推断新操作。
四条已建立轨迹中暂时遮挡的一槽，可在另外三槽持续支持共同几何时保留。若始终无法确认四槽身份，
可靠T轨迹的真实越界仍可关闭该组并继续下一组；该组保留provisional和pending，不虚构S号或复用其上下料基线。

单纯漏检、手遮挡和突然跳出匹配范围不会产生真实越界证据；但只要有一个已匹配槽的真实中心越过ROI边界，
就会触发换组。因此ROI边界应留出足够余量，避免正常抖动落到ROI外。
EXIT_MIN_MOTION_RATIO和MOTION_PAUSE_RATIO仅供恢复多点换组规则时使用，当前单点配置不参与触发。

“组已关闭”只表示离开操作位置。该组是否合格仍取决于四槽状态及顺时针证据；证据不足结果是pending。

## 灰色检测框、灰色状态点与黄色预测框

视频中的灰色框和灰色点含义不同，不能只根据颜色判断置信度。

### 灰色检测框

浅灰色检测框使用颜色`(150,150,150)`，表示这是YOLO输出的槽位检测框，但当前没有有效的ByteTrack ID：

- 检测框刚出现，ByteTrack还没有建立轨迹；
- 检测分数较低，只参与了ByteTrack的低分关联；
- 原轨迹因遮挡、快速移动、位置跳变或框重叠而没有关联成功；
- 空槽框和满槽框存在冲突，当前检测无法确定对应的持续轨迹；
- 当前框是单帧或短时出现的候选框。

浅灰色只表示“当前没有`track_id`”，不等于检测框一定是误检，也不等于置信度一定低。具体置信度应查看框旁数值或`detection_confidences.csv`中的`confidence`、`smoothed_confidence`和`display_reason`。当前规则下，无`track_id`的槽位框只用于视频显示和CSV审计，始终不进入槽位状态机；它不能创建临时槽位、参与几何初始化、确认空满状态或触发组切换。只有后续获得有效`track_id`的检测框，才按正常轨迹处理。

如果`SHOW_ALL_DETECTION_BOXES=True`，输出视频会保留符合审计下限的真实检测框，包括低分框和ROI外框，因此浅灰框可能出现在ROI外。浅灰框不会因为连续出现或置信度较高就自动参与槽位映射；后续获得有效ID时才转为正常轨迹。局部补检框只用于已经建立的槽位，不用于创建新槽位。

深灰色检测框使用颜色`(120,120,120)`，表示该框虽然有ByteTrack ID，但这个ID已经属于已关闭的旧组。标签通常会追加`OLD`。这类框只用于显示旧组残留轨迹和诊断，不参与当前组的槽位映射；审计记录中的原因通常是`previous_group_track`。

灰色框的常见排查顺序是：

1. 查看是否有`track_id`；没有则是未建立或未关联ByteTrack轨迹。
2. 查看`confidence`和`smoothed_confidence`，确认是否接近低分阈值。
3. 查看`display_reason`或`mapping_reason`，区分`below_confidence_threshold`、`outside_slot_roi`、`previous_group_track`、`transition_roi_quarantine`和`association_ambiguous_or_too_far`。
4. 对照前后帧的框中心，检查是否发生遮挡、跳变、框重叠或轨迹ID切换。

### 灰色状态点

灰色状态点使用颜色`(160,160,160)`，表示槽位的空满状态为`unknown`。状态点为中空圆，而空槽和已填充状态使用实心圆。

灰色空心点可能由以下情况产生：

- 当前帧没有检测到对应槽位框；
- 槽位框被手或其他目标遮挡；
- 空槽和满槽检测分数过于接近，触发冲突抑制；
- 轨迹刚建立，连续确认帧数或确认时间尚未满足；
- 组正在进入、转位或退出，当前只保留历史参考位置；
- 临时槽位已经失去当前检测，但尚未达到清理时限；
- 该位置是临时几何点或旧组参考点，不能作为当前帧的真实检测证据。

灰色空心点可能出现在ROI外。`overlay_status()`只检查点是否位于画面范围内，不再次用ROI裁剪状态点；因此旧参考位置、临时点或预测位置离开ROI后仍可能显示为灰色空心点。它不会因此自动产生新的槽号，也不应作为真实越界证据。

正式编号前，如果灰色点对应的槽位在当前帧重新有真实检测框，并且该框已有确认的空/满状态，代码会显示对应的实心状态点；没有当前真实框时仍保持空心灰点，避免把历史位置误认为当前检测。

### 黄色虚线预测框

黄色虚线框是几何预测位置，不是YOLO直接检测出的真实框。它只在已有可靠槽位共同支持运动、缺失位置满足预测条件且预测中心仍在ROI内时绘制，并带有`PRED`标记。

旧组离开时不再生成尾部预测点，也不再绘制蓝色虚线框；旧组排除只使用真实检测框和真实轨迹，改 ID 恢复也必须由多个真实旧轨迹共同支持。视频中的虚线框只表示当前槽位的黄色几何预测。

预测框可以帮助观察槽位在短时漏检或遮挡期间的预计位置，但不能单独确认空满状态、触发ROI越界或建立新组。当前代码对推算出的旧组S4还会在组切换后禁止用新ByteTrack ID重新绑定，避免预测点把新组检测框错误归入旧组。

三种显示的区别可以概括为：

| 显示 | 产生来源 | 是否真实YOLO框 | 是否有当前ByteTrack ID | 是否直接参与槽位映射 |
| --- | --- | --- | --- | --- |
| 浅灰实线框 | 真实槽位检测但未关联轨迹 | 是 | 通常没有 | 否，仅显示和审计 |
| 深灰实线框 | 已关闭旧组的轨迹框 | 是 | 有 | 不参与当前组映射 |
| 灰色空心点 | 槽位状态为`unknown`或没有当前证据 | 不一定 | 不一定 | 不作为单独证据 |
| 黄色虚线框 | 根据可靠槽位几何关系预测 | 否 | 不代表真实检测ID | 不作为单独证据 |

## 首次运行

1. 打开脚本，确认 SOURCE_VIDEO、MODEL_WEIGHTS。旧分组入口当前默认使用 exp3.3；ByteTrack跟踪`wafer_slot_empty`和`wafer_slot_filled`槽位框，两类检测共用同一跟踪器，轨迹稳定后再按槽位几何映射为S1–S4。普通检测入口的权重配置保持不变。
2. 默认 CURRENT_GROUP_ID=1、PROCESS_PHASE="unload"、AUTO_LOAD_AFTER_UNLOAD=True，自动完成下料到上料的切换。
   视频中途开始时填当前真实组号和起始工序；只有纯上料片段才需要手动设PROCESS_PHASE="load"。
3. 运行脚本，默认打开现有 UI7V。“槽位 ROI”可选“读取配置”或“手动划分”，然后点击“开始检测”。
   默认读取第一次验证通过的ROI；选择其他JSON即可复用已有标定。手动模式可选保存路径，开始时弹出圈选窗口。
4. 不再打开四槽标定窗口，也不读取旧的 `<视频名>_four_slots.json`。
   槽中心直接取检测框 `(x1+x2)/2, (y1+y2)/2`。
5. ROI内去重后首次检测到三个槽时，下料阶段仅在四槽近似正方形/圆周关系表明缺失位置为S4时推算其中心；若缺失其他槽或几何不成立，则继续等待真实槽框。上料仍等待四个真实槽中心。
   首组每槽都曾无遮挡地匹配，至少三个可靠可见槽支持稳定几何达到0.3秒及2帧后，启用正式编号。
   此时即使一槽被手遮挡，也不再要求四槽同时无遮挡。身份确认时按参考姿态正式映射，之后不重排。
6. 缺失位置确认是S4时，才为S4更新预测中心并显示虚线跟踪框；S1–S3及其他缺失槽不做几何外推，也不显示预测框。下料S4手接触达到门限并离手后，
   若YOLO仍未给出可确认空/满状态，可按手接触规则记录推断事件；事件`confirmation_source`为`hand_contact`。
   初始多于四槽时仍等待，避免擅自取高分四框。ROI外缓冲带中的点只用于后续追踪，不参与初始化。

固定ROI保存在`industrial_inspection/configs/slot_roi.json`，使用第一次验证通过的区域，
640×480参考坐标约为`(279,157)、(628,241)、(633,387)、(300,321)`，同宽高比按分辨率缩放。
普通检测入口与四槽分组入口默认共用此配置；视频改名、移动目录或旁边存在旧ROI文件都不会改变默认区域。
界面切到“手动划分”时默认保存到当前视频旁的`<视频名>_slot_roi.json`，也可以选择其他保存文件。
划分成功后自动切回“读取配置”并复用刚保存的结果；取消圈选不启动推理，也不修改已有配置。
配置缺失或画面宽高比改变时明确报错，不自动弹窗或切换区域。
也可在两个入口脚本顶部设置`SLOT_ROI_FILE`、`ROI_RESELECT`及`ROI_SELECT_FRAME`，或使用命令行参数。

ROI应排除上方槽位，并覆盖同一游星片可见的至少三个槽和推算出的S4接触中心。
恰好检测到四个框本身不能证明四槽同组。ROI需在操作时只包含一组；过宽且同时包含其他静止槽会影响初始化。
新旧组短暂同时出现时，单点模式继续排除旧组尾部，同时跟踪新点；多余候选不用于凑足四槽。
对已有新组轨迹，门限内且更靠近新点的框保留给新组，避免旧点漏检后误接新点并持续排除。
新组即使只有一个点也保存临时状态；下料阶段三条有效槽轨迹仅在缺失位置为S4时可推算中心并进入稳定确认，上料阶段仍需收齐四个真实中心。
初始化阶段的画面和状态栏使用ByteTrack ID标识检测框，不再显示临时T号；内部仍保留槽位索引用于状态缓存和几何恢复。正式编号完成后同时显示ByteTrack ID与S1-S4映射。
默认只保留最近5秒内有原状态和新状态证据的事件，不会因为是下料工序就假定初始四槽全满。

检查首次输出的槽号与实际顺时针关系。当前SLOT2_BELOW_SLOT3=True适用于本相机的左上S1、
顺时针1→3→4→2参考姿态；“S2在S3下方”是辅助约束，允许小幅透视和框中心抖动。
换相机或参考姿态时需核对S1起点与CLOCKWISE_ORDER。设为False可保留按x建立编号的通用模式。
默认从第0帧开始，也可用 START_FRAME 选择当前组开始的源帧号。

空满状态以 YOLO 连续确认结果为主。仅 S4 的手接触达到门限并离开后，如果 YOLO 仍持续为unknown，
且接触前已有 confirmed 状态，则按基线反转：`empty → filled`、`filled → empty`，不受当前工序方向限制；
下料时若接触前一直为unknown，则在有效手接触达到时长和帧数门限后，先假定基线为`filled`，离手后仍为unknown
就推断为`empty`；上料时没有此前状态则不猜测。对接触后仍漏检的槽位等待短暂恢复期，
再依据unknown状态补事件；若YOLO恢复并确认新状态，仍由YOLO作为确认来源；若确认的还是接触前状态，
则取消这次接触推断。S1–S3不记录手接触状态证据；接触身份失效、位于ROI外或检测到其他明确状态时，不做手接触推断。

自动回到同一组上料时，正式槽号建立后，可复用该组此前下料真实确认过的空槽
作为历史基线，不复用旧坐标。前提是转位顺序、同组槽号对应关系可靠；此前
未确认空槽的槽位不能假定为空。若上料在正式编号前已发生，已有空槽基线和
本轮真实满槽证据可补报上料，时间区间仍使用两次视觉证据，无法分清顺序时为pending。

一点出ROI仍立即切换新组；有待核验空槽的旧上料组继续核验最多
`IDENTITY_LOST_SECONDS`（默认1.2秒），不要求先检测到手。旋转后检测到填充，
须通过原槽的逐点位置关联及正常连续确认，生成empty→filled事件并归属旧组，
不会把该框用作新组初始化。超过核验时间仍无满槽证据就保留未确认。
S4未被YOLO检测时，须由其余三个槽的有效几何关系推算中心并建立身份；单靠手框不能凭空生成S4。
本相机已完成合成序列、真实检测框回放和现有权重的3487帧整段视频验证。

首组模板的距离门限小于最小槽间距的一半；逐点模式使用固定像素门限，配合匈牙利一对一匹配和歧义拒绝。
本版运动跟随适合小幅连续运动；大幅跳转、严重透视变化和四槽对称旋转可能无法可靠关联。
长时间没有任何槽位匹配且未确认退出时锁定identity_lost，显示组身份待确认，当前状态为unknown。
这时不会自动给新组继承编号或仅凭新出现四槽继续加组号。需从组号已知的片段重新开始。

默认 UI_ENABLED=True，使用原 UI7V 的开始、停止和状态栏；固定ROI自动读取，显式重标定才在GUI主线程圈选。
设置 UI_ENABLED=False、SHOW_PREVIEW=True 时使用OpenCV预览，空格暂停/继续、Q/Esc停止。
身份丢失后不会自动重排四槽并解除锁定。应停止运行，确认当前组片段及组号后重新开始；
重新开始是一份新记录，不自动接续上次事件历史。

## 显示与结果含义

视频中 `G2-S4 filled` 表示组2、槽4、已确认填充。绿色点为filled，橙色点为empty，
灰色空心圈为unknown。未匹配到框时的点是保留或预测位置，不是当前看见该槽的证据。
已匹配到框但状态确认中、冲突或遮挡时，点来自检测框中心，状态仍为unknown。
新组槽位尚未完成几何确认时只显示ByteTrack ID（例如BT41 filled），不输出临时T槽号；完成一次性映射后才显示正式槽号（例如G2-S2 filled）。
左上角只显示当前组是否完成工序（例如`G5 Unload: completed`），不再列出四槽状态或顺序调试信息。
四个不同槽均记录过当前工序的操作，且最后确认均达到目标状态时显示completed；否则显示not completed。
完成提示与顺序是否合格分开：顺序判定仍保存在日志和JSON结果中。
各槽编号和状态仍标注在中心点旁；尚未检测到的槽无坐标，漏检不会把已有点号删掉。

- `state`：当前帧经过确认后的状态；漏检、确认中、遮挡或冲突时为unknown。
- `observation`：当前帧候选空满观测；不等于已确认状态。
- `last_confirmed_state`：历史最近确认状态，不能作为当前仍然可见或状态未变化的证明。
- `position_is_prediction`：仅在S4由三个真实槽位的几何关系成功外推且当前没有真实整图检测时为true；其他未检测槽不显示虚拟跟踪框。
  已关联整图框但空满冲突/遮挡时，该值为false，填充状态仍可为unknown。局部补检可确认空满，但不会更新几何位置。
- `center_xy`：尚未建立轨迹时为null；临时轨迹已有实际检测中心时输出该中心，CSV采用相同规则。
- `slot_numbering_status`：provisional时`slot_id`和`formal_slot_id`为空，槽位状态只通过ByteTrack ID显示；`internal_slot_index`仅供缓存诊断，不是槽号。final时建立正式S1-S4映射。
- `formal_slot_id`：只有`slot_numbering_status=final`时才有值；临时轨迹记录使用`byte_track_id`，避免把内部缓存索引误当作槽号。
- `group_transform`：2×3仿射/相似变换，把S1–S4映射建立时的稳定图像坐标变换到当前图像坐标；它不是相机标定后的物理世界坐标。
- `transform_valid_this_frame`、`transform_fit_error`、`transform_support_slot_ids`、`transform_support_byte_track_ids`：本帧是否获得有效拟合、误差，以及支持拟合的正式槽号和ByteTrack ID。少于三个可靠检测时保留最近一次矩阵，但该帧有效标志为false。
- `initialization`：自动初始化进度、候选槽数、连续帧数、成功时刻和首次四槽中心。
  未初始化时identity_status为waiting_initialization，不会因为等待时间长就锁定丢失。
  `provisional_started_at`为候选轨迹开始时间；正式编号前用`geometry_seen_track_ids`记录曾可靠看见的ByteTrack轨迹，编号后才填`geometry_seen_slot_ids`，
  `buffered_event_count`为身份确认时准备发布的缓存事件数（确认后保留该次初始化统计）。
- `pending_initialization`：等待下一组时，下一组候选轨迹的初始化进度；其余时间为null。
- `group_status`：initializing、entering（单点模式逐点进入）、active、exiting、waiting_next、stabilizing_next、identity_uncertain或sequence_complete。
- `local_redetection`：逐帧JSON中的局部补检记录，含原组号、槽号、裁剪区域及接收的框（均为原图坐标）。
  接收的框仍须满足关联、遮挡、空满冲突和连续确认条件，不能把接收到候选框等同于确认一次操作。
- `pending_group_id`：多点模式等待接管的新组号；单点模式已立即切换group_id，该字段为空。
- `pending_phase`：待接管工序；下料G5退出后为load、pending_group_id为1，其他时间可为空。
- `crossed_slot_ids` / `required_exit_slots`：当前真实越界槽号及要求的槽数，供排查为何还未换组。
- `motion_support_slot_ids`：实际检测中心支持整组外移的槽号；`group_exiting`事件也保存`moving_slot_ids`。
- `current_target_count`：当前确认达到本工序目标状态的槽数，下料目标empty，上料目标filled。
- `last_verified_target_count`：四槽分别最后一次确认的目标状态数量，可跨不同时间累计。
- `all_four_currently_confirmed`：当前四槽同时确认达到目标。
- `all_four_target_previously_verified`：四槽各自最近确认均达到目标；并不证明遮挡中没有再次取放。

原右下角槽旋转后可见，只有位置匹配可靠且持续检测到状态，才更新对应槽；
此前须已完成四槽初始化。若身份已锁定丢失，保持unknown，待重新运行已核实的组片段。
本版不凭“其他三个已经完成”推断第四个。

## 顺时针判断

默认顺时针环1→3→4→2，允许任意起点。自动流程中上料、下料分别检查，使用同一环。

- `pass`：已确认四个不同槽位的对应操作，时间证据支持的所有顺序均符合该环。
- `fail`：明确逆序、重复操作，或观察到与当前工序相反的操作。
- `pending`：事件不完整或时间先后无法确定。它不等于不合格。

每个事件保留最后确认原状态至首次观察新状态的时间区间，以及多帧确认时间。
`reported_at`是事件写入正式事件流的时间；`recovered_before_initialization=true`表示事件在身份确认前
已满足多帧确认条件，身份确认后才补报。顺序判断使用原始`time_lower`/`time_upper`，不使用补报时间。
上料复用同组下料空槽基线时，补报采用当前满槽状态首次成立的观测与确认时间，
不使用遮挡恢复后的候选起始时间或最近一次复核时间。逐帧槽记录中的`confirmed_state_since`、
`confirmed_state_first_confirmed_at`分别保留这两个时间，`last_confirmed_at`仍表示最近一次确认。
遮挡后多个槽一起变化时，不把检测恢复顺序当作操作顺序；若合法和不合法顺序都可能，返回pending。
只有三个事件时不会凭缺失槽的编号补出第四次操作。没有此前真实原状态证据时，初次看见某槽已满/已空只建立基线。

## 输出文件

每次创建 `<视频名>_slots_<时间>` 独立目录：

- `annotated.mp4`：中心点、组号槽号、状态面板，无原视频音轨。
- `slot_tracks.jsonl`：每帧的槽位检测框、ByteTrack ID、关联槽位状态、最近确认状态及观测原因；映射中保留内部槽位索引，并在正式编号后附带S1-S4。未映射检测框的槽位状态记为unknown；低置信度框只参与ByteTrack关联。
- `slot_states.jsonl`：每帧一条，完整四槽状态、关联失败候选、顺序结果及当帧事件。
- `slot_states.csv`：每帧四行，含phase工序、组号、槽号、ByteTrack ID、当前状态、历史确认状态、坐标和原因。
- `slot_events.jsonl`：确认的取放事件及时间区间，供人工复核顺序。
- `group_events.jsonl`：退出候选、退出取消、旧组关闭、新组接管、phase_changed工序切换及退出后核验更新事件。
- `group_summaries.json`：所有已确认退出组的独立结果，含各自槽位状态、操作事件和operation_result。
- `group_process_report.txt` / `group_process_report.json`：处理结束时按工序分别保存五组四槽完成矩阵和逐组操作顺序。
- `summary.json`：本次参数、结束原因、最终组状态、已关闭组的结果及所有取放事件。
  `slot_tracking`记录ByteTrack阈值、轨迹数量和每条轨迹的持续时间。标注视频在槽位框旁显示BT轨迹ID；正式映射完成后同时显示其S1–S4槽号。低分框不进入槽位状态机，ROI exit gate仍负责组切换。
  未退出的当前组在final_group_snapshot中，不会当作已完成组保存到closed_groups。
  `group_process_reports.unload`和`group_process_reports.load`分别保存上下料汇总，含matrix、逐组sequence和order_result。
  `group_process_report`兼容保留起始工序汇总；`phase`为起始工序，`current_phase`为结束时所在工序。
  同号组通过phase区分，例如下料G1与上料G1各自独立保存，不会覆盖。

运行日志仅在群组完成状态变化时输出，例如“游星片1：下料未完成”“游星片1：下料完成”；
不再输出逐槽状态、初始化坐标、转位和每次取片信息。详细证据仍保存到逐帧和事件文件。
视频处理结束后，日志统一按下料、上料输出各自五组四槽的完成矩阵和检测到的操作顺序。
矩阵1表示有已确认的对应工序事件且最后确认达到目标状态，0表示未确认完成，未检测到的组用“-”。
仅在开始时看到空槽不算已检测到下料；尚未退出的当前组也参与汇总。

## 轨迹状态与组编号分离（2026-10-23）

入口仍是 `industrial_inspection/tools/predict_slot_groups.py`，沿用 exp3.3 和现有 ROI。
`slot_track_state.py` 按视频内持续的 BT ID 独立累计 YOLO 空/满状态和视觉变化历史。
尚未建立组或 S 号的框也可显示 `filled/empty S:pending`，不能把“槽号待定”统一当作空满 unknown。
空满仍须满足 `CONFIRM_SECONDS` 和 `MIN_CONFIRM_FRAMES`；手遮挡、空满冲突、ROI 外和暂停检测不确认视觉状态。
低置信度框仍只供 ByteTrack 关联，不累计工艺状态。

候选被正式接收时恢复该 BT 轨迹先前的基线及视觉事件，并保留原始发生时间。
正式 S 号建立后再发布缓存工艺事件；同一事件只回填一次。
只对 S4 应用现有手接触补判；下料三点推算仍只允许补 S4，不推算缺失的 S1/S2/S3。

换组时不重置 ByteTrack。旧组身份优先按 ID 隔离，不能仅凭新框靠近旧中心就排除新框。
旧 ID 变化时，需共同可见的旧轨迹提供一致运动及严格位置约束，才恢复旧组归属；
预测 S4 的真实框恢复也需要旧组共同运动支持。
轨迹从 ROI 真正离开一段时间后重新从入口进入，可开始新一轮访问，避免同一载体上料时被永久列为旧组。

当前组正式编号后，任意一个已关联真实槽位越过出口仍立即关闭该组。
新组在 `entering` 阶段只记录候选轨迹和状态，未完成正式几何身份的临时点越界不会继续推进组号。
若一直缺少非 S4 的真实槽位，保持身份待确认；不会用临时点越界猜测下一组。

对持续真实支持的四框组合，比较凸四边形、槽间距离和对角线中点关系。
只有几何上有明确优势的组合才用于纠正早期错误临时槽；保留未被替换轨迹的状态和事件。
不按置信度取前四框；多个布局仍有歧义时继续等待。此项是图像几何关系，不要求四点精确共圆。

输出新增 `slot_tracks.csv`，每个处理帧的所有检测框（包括未映射和低分框）均有明细，
包含 BT ID、组/槽号、状态、`mapping_status`、`mapping_reason` 和 `state_reason`。
无 BT ID 的单帧检测只记录原始观测，不伪造持续轨迹。
`mapping_reason` 用于区分 `previous_group_track`、`new_track_outside_entry_region`、
`outside_supported_group_geometry`、`waiting_group_geometry`、`waiting_slot_numbering`、
