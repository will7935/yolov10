# ROI自动分组与四槽检测

直接运行 [predict_slot_groups.py](E:/GitHub/yolov10/industrial_inspection/tools/predict_slot_groups.py)。
复用原 predict_video.py 的视频路径、权重、ROI 和 UI7V 界面，不修改原入口。

## 本版实现范围

- 用ROI内YOLO检测框的中心自动初始化四槽，按x从左到右编号，x相同再按y从上到下。
- 起始组号可配置为 1..5；当前单点换组模式下，旧组任一真实中心越出ROI就立即递增组号，开始跟踪新点。
  新点按出现顺序显示临时点号T1..T4并记录空满；收齐四条轨迹后按x排序映射一次正式槽号S1..S4，状态历史随点继承。
- 单点换组后的新组全程按真实中心逐点匹配（当前40像素），不把一两个点的移动外推到其他槽。
  首组及多点模式在小幅连续移动/旋转时，至少三个可靠匹配槽共同支持相似变换，才更新未检出槽的预计位置。
  当前检测中心与编号参考位置分开保存；只有一两个槽可见时仅显示各自的检测中心，
  不改变整组关联模板，避免把框中心抖动外推为整组运动或造成槽间距不断缩小。
- 输出组号、槽号和 empty / filled / unknown，支持手部遮挡和空满冲突抑制。
- 空满状态需要连续满足时间和帧数条件；初次确认状态不算操作事件。
- 首组候选四槽出现时开始记录；单点换组后的新组从第一个新点开始记录，不要求四槽同时出现，也不等待停稳。
  组身份确认后补报缓存窗口内已有可靠证据的取放事件，保留原始操作时间区间。
- 上料记录 empty→filled，下料记录 filled→empty；两种工序使用同一顺时针环。
- 保存每帧四槽结果、取放事件和摘要，UI 和输出视频显示相同编号与状态。
- 沿用现有权重和ROI，每帧整图推理一次；操作中已编号槽被整图漏检时，自动裁剪局部图补检。
  局部补检只补充空满观测，不改变槽位轨迹、不触发换组，也不用于新组初始化。
- 组号来自已知起始组号与换组次数，不是凭单张图片识别物理游星片。
- 默认自动运行 `下料 G1→G5 → 上料 G1→G5`。下料G5实际退出ROI后立即进入上料G1，
  上料G5退出后显示“工序结束”。未确认完成的下料槽仍记录为未完成，不会阻塞下一物理组的跟踪。
- 手接触只记录为遮挡和待核验信息，不能证明上料或下料；上料必须有真实的empty→filled视觉证据。

## 换组判断

```text
首组四槽初始化 → 操作中 → 任一真实中心越界 → 新组逐点记录 → 收齐四槽后正式编号
                            ↓
                 遮挡/匹配证据不足：组身份待确认，保持组号
```

1. 每槽必须实际检测到从ROI边界内4像素以上，移动到边界外4像素以上；未检测到的预测点不计越界。
2. 当前配置为单点换组：任意一个已编号槽的真实检测中心从ROI内越到ROI外，
   同一帧关闭旧组并切到下一组，不再等待多个槽、停稳或退出计时。
3. 新组第一个点出现时即跟踪、显示并记录状态；还没出现的槽保持unknown和空坐标。
   单点越界只触发换组，不把预测点或漏检点当成越界证据。
4. ROI外40像素内只保留能与当前组编号匹配的框；这些框只用于退出跟踪，不确认空满，也不建立新编号。
5. 旧组关闭后继续逐点跟随旧中心，排除残留点。新点按NEXT_GROUP_MATCH_DISTANCE_PX（当前40像素）
   与上一帧中心一对一匹配；未匹配且不在已知点附近的点才建立新轨迹。
6. 四条轨迹都曾无遮挡地看见后，按当前x从左到右、x相同按y排序，映射一次正式槽号。
   不再等待NEXT_GROUP_STABLE_SECONDS。临时阶段确认的取放事件在映射时补报，原始时间区间不变。
   正式编号后继续沿用逐点匹配，空满框中心偏移只更新对应槽；不可见槽保留上次位置。
   空满判断仍满足CONFIRM_SECONDS及MIN_CONFIRM_FRAMES；手遮挡或空满冲突仍输出unknown。

EXIT_MIN_SLOTS大于1时保留原多点模式，才使用EXIT_CONFIRM_SECONDS和NEXT_GROUP_STABLE_SECONDS等停稳参数。

单纯漏检、手遮挡和突然跳出匹配范围不会产生真实越界证据；但只要有一个已匹配槽的真实中心越过ROI边界，
就会触发换组。因此ROI边界应留出足够余量，避免正常抖动落到ROI外。
EXIT_MIN_MOTION_RATIO和MOTION_PAUSE_RATIO仅供恢复多点换组规则时使用，当前单点配置不参与触发。

“组已关闭”只表示离开操作位置。该组是否合格仍取决于四槽状态及顺时针证据；证据不足结果是pending。

## 首次运行

1. 打开新脚本，确认 SOURCE_VIDEO、MODEL_WEIGHTS。默认沿用原脚本，也可直接改为自己的 Path(r"...")。
2. 默认 CURRENT_GROUP_ID=1、PROCESS_PHASE="unload"、AUTO_LOAD_AFTER_UNLOAD=True，自动完成下料到上料的切换。
   视频中途开始时填当前真实组号和起始工序；只有纯上料片段才需要手动设PROCESS_PHASE="load"。
3. 运行脚本，默认打开现有 UI7V，点击“开始检测”。没有 ROI 文件时先圈选槽位区域；已有文件直接加载。
4. 不再打开四槽标定窗口，也不读取旧的 `<视频名>_four_slots.json`。
   槽中心直接取检测框 `(x1+x2)/2, (y1+y2)/2`。
5. ROI内去重后首次恰好四个槽时，先按x从左到右建立候选编号，并开始逐槽确认空满。
   首组每槽都曾无遮挡地匹配，至少三个可靠可见槽支持稳定几何达到0.3秒及2帧后，启用正式编号。
   此时即使一槽被手遮挡，也不再要求四槽同时无遮挡。只在候选轨迹开始时排序，之后不重排。
6. 初始只有三个槽时，尚未建立轨迹的槽位坐标为空，左上角显示工序未完成，等待四槽齐全。
   初始多于四槽时也等待，避免擅自取高分四框。ROI外缓冲带中的点只用于后续追踪，不参与初始化。

ROI仍需圈选或加载已有文件，它应排除上方槽位并在操作时包含同一游星片的四槽。
恰好检测到四个框本身不能证明四槽同组。ROI需在操作时只包含一组；过宽且同时包含其他静止槽会影响初始化。
新旧组短暂同时出现时，单点模式继续排除旧组尾部，同时跟踪新点；多余候选不用于凑足四槽。
对已有新组轨迹，门限内且更靠近新点的框保留给新组，避免旧点漏检后误接新点并持续排除。
新组即使只有一个点也保存临时状态，正式槽号需要累计收齐四槽，不要求同帧出现。
临时T号仅表示出现顺序，正式S号可能不同；读取逐帧结果时应结合slot_numbering_status。
默认只保留最近5秒内有原状态和新状态证据的事件，不会因为是下料工序就假定初始四槽全满。

检查首次输出的槽号与实际顺时针关系，再设置 CLOCKWISE_ORDER；不同初始姿态下，
按x排序不保证顺时针环必然是1→3→4→2。该配置目前不会由几何角度自动重算。
默认从第0帧开始，也可用 START_FRAME 选择当前组开始的源帧号。

## 常用配置

```python
CURRENT_GROUP_ID = 1           # 起始实际组号，后续自动递增
PROCESS_PHASE = "unload"       # 起始工序；纯上料片段可设"load"
AUTO_LOAD_AFTER_UNLOAD = True  # 下料G5退出后进入上料G1；False只运行起始工序
CLOCKWISE_ORDER = (1, 3, 4, 2)
AUTO_GROUP_SWITCH = True       # False：单组模式
EXIT_CONFIRM_SECONDS = 0.1    # 仅多点模式使用，单点模式立即换组
EXIT_MIN_SLOTS = 1            # 任意一个已编号槽实际越出ROI即触发换组
PARTIAL_EXIT_MIN_SLOTS = 1    # 单点换组模式下同样只需要一个越界槽
EXIT_BOUNDARY_MARGIN_PX = 4
ROI_TRACKING_MARGIN_PX = 40
EXIT_MIN_MOTION_RATIO = 0.5
MOTION_PAUSE_RATIO = 0.18
NEXT_GROUP_STABLE_SECONDS = 0.3 # 仅多点模式使用
NEXT_GROUP_STABILITY_RATIO = 0.12
NEXT_GROUP_MATCH_DISTANCE_PX = 40 # 单点模式逐帧匹配距离，单位像素
EXIT_DIRECTION = (-1,-1)      # camera_B首次转位已核实向左上；不确定时填None自动判断

LOAD_HAND_CONTACT_ENABLED = True       # 仅上料时把手接触作为辅助证据
LOAD_HAND_CONTACT_SECONDS = 0.15        # 连续接触时长
LOAD_HAND_CONTACT_MIN_FRAMES = 2        # 最少接触帧数

CONFIDENCE = 0.35              # 脚本默认沿用原入口的阈值，可直接改成数字
MATCH_DISTANCE_RATIO = 0.46    # 匹配门限为当前最小槽间距的0.46倍，容纳空/满框中心偏移；必须小于0.5
CONFIRM_SECONDS = 0.2          # 当前脚本设置；与帧数条件同时满足才确认
MIN_CONFIRM_FRAMES = 3
IDENTITY_LOST_SECONDS = 1.2
INITIALIZATION_SECONDS = 0.3
MIN_INITIALIZATION_FRAMES = 2
INITIALIZATION_HISTORY_SECONDS = 5.0 # 身份确认前的取放证据时间窗口
LOCAL_REDETECT_ENABLED = True
LOCAL_REDETECT_CROP_SIZE = (180, 140) # 原图裁剪宽、高（像素）
LOCAL_REDETECT_IMAGE_SIZE = 320      # 局部图推理尺寸；置信度仍使用CONFIDENCE

START_FRAME = None            # 从第0帧开始，或指定当前组的源帧号
END_FRAME = None              # 可限定某个源帧结束，不包含该帧
MAX_FRAMES = 0                # 处理整段，包含后续上料；设为正数可限制试跑帧数
ROTATION_INTERVALS = []       # 可填[(源视频开始秒数,结束秒数)]，暂停状态确认但继续跟踪
```

上料仅采用 YOLO 的 `empty → filled` 连续确认。手接触可能是取片、放片或整理，
只用于遮挡和待核验记录，不能代替空满证据，也不用接触时刻推断操作顺序。
手接触后仍确认为空、一直漏检、自然结束或手动停止，都不会补成已上料。

自动回到同一组上料时，正式槽号建立后，可复用该组此前下料真实确认过的空槽
作为历史基线，不复用旧坐标。前提是转位顺序、同组槽号对应关系可靠；此前
未确认空槽的槽位不能假定为空。若上料在正式编号前已发生，已有空槽基线和
本轮真实满槽证据可补报上料，时间区间仍使用两次视觉证据，无法分清顺序时为pending。

一点出ROI仍立即切换新组；有待核验空槽的旧上料组继续核验最多
`IDENTITY_LOST_SECONDS`（默认1.2秒），不要求先检测到手。旋转后检测到填充，
须通过原槽的逐点位置关联及正常连续确认，生成empty→filled事件并归属旧组，
不会把该框用作新组初始化。超过核验时间仍无满槽证据就保留未确认。
S4如果从未被定位，仍需先建立其中心及身份；单靠手框不能凭空生成S4。
当前只完成合成检测序列和回归验证，上料视频与现有权重仍需实际回放核验。

距离门限小于最小槽间距的一半，配合匈牙利一对一匹配和歧义拒绝，减少一个点继承多个编号。
本版运动跟随适合小幅连续运动；大幅跳转、严重透视变化和四槽对称旋转可能无法可靠关联。
长时间没有任何槽位匹配且未确认退出时锁定identity_lost，显示组身份待确认，当前状态为unknown。
这时不会自动给新组继承编号或仅凭新出现四槽继续加组号。需从组号已知的片段重新开始。

默认 UI_ENABLED=True，使用原 UI7V 的开始、停止和状态栏；ROI圈选在GUI主线程完成。
设置 UI_ENABLED=False、SHOW_PREVIEW=True 时使用OpenCV预览，空格暂停/继续、Q/Esc停止。
身份丢失后不会自动重排四槽并解除锁定。应停止运行，确认当前组片段及组号后重新开始；
重新开始是一份新记录，不自动接续上次事件历史。

## 显示与结果含义

视频中 `G2-S4 filled` 表示组2、槽4、已确认填充。绿色点为filled，橙色点为empty，
灰色空心圈为unknown。未匹配到框时的点是保留或预测位置，不是当前看见该槽的证据。
已匹配到框但状态确认中、冲突或遮挡时，点来自检测框中心，状态仍为unknown。
新组四槽未收齐时显示临时点号（例如G2-T1 filled）；收齐后显示正式槽号（例如G2-S2 filled）。
左上角只显示当前组是否完成工序（例如`G5 Unload: completed`），不再列出四槽状态或顺序调试信息。
四个不同槽均记录过当前工序的操作，且最后确认均达到目标状态时显示completed；否则显示not completed。
完成提示与顺序是否合格分开：顺序判定仍保存在日志和JSON结果中。
各槽编号和状态仍标注在中心点旁；尚未检测到的槽无坐标，漏检不会把已有点号删掉。

- `state`：当前帧经过确认后的状态；漏检、确认中、遮挡或冲突时为unknown。
- `observation`：当前帧候选空满观测；不等于已确认状态。
- `last_confirmed_state`：历史最近确认状态，不能作为当前仍然可见或状态未变化的证明。
- `position_is_prediction`：当前没有关联到检测框，显示的是保留或预测位置。
  已关联整图框但空满冲突/遮挡时，该值为false，填充状态仍可为unknown。
  局部补检可确认空满，但显示位置仍保留整图跟踪位置，此时该值为true。
- `center_xy`：尚未建立轨迹时为null；临时轨迹已有实际检测中心时输出该中心，CSV采用相同规则。
- `slot_numbering_status`：provisional为临时T号，final为正式S号；映射时状态、事件、槽号一起转换。
- `initialization`：自动初始化进度、候选槽数、连续帧数、成功时刻和首次四槽中心。
  未初始化时identity_status为waiting_initialization，不会因为等待时间长就锁定丢失。
  `provisional_started_at`为候选轨迹开始时间，`geometry_seen_slot_ids`为曾可靠看见的槽号，
  `buffered_event_count`为身份确认时准备发布的缓存事件数（确认后保留该次初始化统计）。
- `pending_initialization`：等待下一组时，下一组候选轨迹的初始化进度；其余时间为null。
- `group_status`：initializing、entering（单点模式逐点进入）、active、exiting、waiting_next、stabilizing_next、identity_uncertain或sequence_complete。
- `local_redetection`：逐帧JSON中的局部补检记录，含原组号、槽号、裁剪区域及接收的框（均为原图坐标）。
  接收的框仍须满足关联、遮挡、空满冲突和连续确认条件，不能把接收到候选框等同于确认一次操作。
- `pending_group_id`：多点模式等待接管的新组号；单点模式已立即切换group_id，该字段为空。
- `pending_phase`：待接管工序；下料G5退出后为load、pending_group_id为1，其他时间可为空。
- `crossed_slot_ids` / `required_exit_slots`：当前真实越界槽号及要求的槽数，供排查为何还未换组。
- `motion_support_slot_ids`：实际检测中心支持整组外移的槽号；`group_exiting`事件也保存`moving_slot_ids`。
- `current_target_count`：当前确认达到本工序目标状态的槽数，下料目标empty，上料目标filled。
- `last_verified_target_count`：四槽分别最后一次确认的目标状态数量，可跨不同时间累计。
- `all_four_currently_confirmed`：当前四槽同时确认达到目标。
- `all_four_target_previously_verified`：四槽各自最近确认均达到目标；并不证明遮挡中没有再次取放。

原右下角槽旋转后可见，只有位置匹配可靠且持续检测到状态，才更新对应槽；
此前须已完成四槽初始化。若身份已锁定丢失，保持unknown，待重新运行已核实的组片段。
本版不凭“其他三个已经完成”推断第四个。

## 顺时针判断

默认顺时针环1→3→4→2，允许任意起点。自动流程中上料、下料分别检查，使用同一环。

- `pass`：已确认四个不同槽位的对应操作，时间证据支持的所有顺序均符合该环。
- `fail`：明确逆序、重复操作，或观察到与当前工序相反的操作。
- `pending`：事件不完整或时间先后无法确定。它不等于不合格。

每个事件保留最后确认原状态至首次观察新状态的时间区间，以及多帧确认时间。
`reported_at`是事件写入正式事件流的时间；`recovered_before_initialization=true`表示事件在身份确认前
已满足多帧确认条件，身份确认后才补报。顺序判断使用原始`time_lower`/`time_upper`，不使用补报时间。
遮挡后多个槽一起变化时，不把检测恢复顺序当作操作顺序；若合法和不合法顺序都可能，返回pending。
只有三个事件时不会凭缺失槽的编号补出第四次操作。没有此前真实原状态证据时，初次看见某槽已满/已空只建立基线。

## 输出文件

每次创建 `<视频名>_slots_<时间>` 独立目录：

- `annotated.mp4`：中心点、组号槽号、状态面板，无原视频音轨。
- `slot_states.jsonl`：每帧一条，完整四槽状态、关联失败候选、顺序结果及当帧事件。
- `slot_states.csv`：每帧四行，含phase工序、组号、槽号、当前状态、历史确认状态、坐标和原因。
- `slot_events.jsonl`：确认的取放事件及时间区间，供人工复核顺序。
- `group_events.jsonl`：退出候选、退出取消、旧组关闭、新组接管、phase_changed工序切换及退出后核验更新事件。
- `group_summaries.json`：所有已确认退出组的独立结果，含各自槽位状态、操作事件和operation_result。
- `group_process_report.txt` / `group_process_report.json`：处理结束时按工序分别保存五组四槽完成矩阵和逐组操作顺序。
- `summary.json`：本次参数、结束原因、最终组状态、已关闭组的结果及所有取放事件。
  未退出的当前组在final_group_snapshot中，不会当作已完成组保存到closed_groups。
  `group_process_reports.unload`和`group_process_reports.load`分别保存上下料汇总，含matrix、逐组sequence和order_result。
  `group_process_report`兼容保留起始工序汇总；`phase`为起始工序，`current_phase`为结束时所在工序。
  同号组通过phase区分，例如下料G1与上料G1各自独立保存，不会覆盖。

运行日志仅在群组完成状态变化时输出，例如“游星片1：下料未完成”“游星片1：下料完成”；
不再输出逐槽状态、初始化坐标、转位和每次取片信息。详细证据仍保存到逐帧和事件文件。
视频处理结束后，日志统一按下料、上料输出各自五组四槽的完成矩阵和检测到的操作顺序。
矩阵1表示有已确认的对应工序事件且最后确认达到目标状态，0表示未确认完成，未检测到的组用“-”。
仅在开始时看到空槽不算已检测到下料；尚未退出的当前组也参与汇总。
达到帧数限制或手动停止时同样保存当前汇总，并注明只包含本次已处理视频范围。

检测分数不是准确率，框中心也不代表物理槽身份或空满真值。实际编号保持和状态准确性仍需在人工核实的视频上验收。

## 局部补检

默认开启。仅在active阶段，对整图未匹配到、参考中心仍在ROI内的已编号槽位，
围绕参考中心裁剪180×140像素区域，用同一权重、同一置信度阈值做320像素推理。
补检框映射回原图后，须在原匹配门限内、更靠近本槽且位于ROI内，才送入原有空满确认流程。
补检检测到的手部也参与遮挡判断。漏检期间若补检仍无框，保持unknown。

补检框不更新几何参考中心、不刷新整组几何存活时间、不作真实越界证据；
同帧切入下一组时丢弃旧组的补检框，避免裁剪框偏移带走编号或引入错误新点。
确认时间仍为0.2秒且至少3帧，不降低确认条件。设置LOCAL_REDETECT_ENABLED=False可关闭补检。
额外推理次数取决于漏检槽数；LOCAL_REDETECT_IMAGE_SIZE更大不一定更准确，应结合实际画面验证。
